# 信用凭据跨机关迁移后的浏览器调档

档案调阅在 `/archive` 操作。选择查询机关并输入合成企业短码，显示索引任务号和当前结果。档页输入格式为 `档号/页号`，成组申请以逗号分隔。开放可单独领取的页面及份数在委托数据内，领取和再查流水均使用门户页面。同名任务号按机关区分。查询批分状态“检索仍在出页”“索引已封”，取档流水为“已受理”“文件可取”“明确未受理”。已受理一次扣一份。
 
档卷用 HTML 页表示电子扫描件，有 `签发号、机关、档号、册页、签发时间、声明适用时间`。新机关接手档页引用原档号和旧机关。扫描页上“联章待核”仅代表当页还缺册次签章信息。原页与重打件用短语标签清楚区分。`data/mandates.json` 给出批准可查看的档页、机关生效区间、份数与范围更新。演练中的有效期和签发时点是整数。

## 本地来源

资料均为合成记录。Node.js 22 环境下执行 `npm ci`，再用 `npm run sources` 启动，默认监听 `127.0.0.1:4180`。可用环境变量 `PORT` 修改端口。在容器中运行时，服务和访问端处于同一网络命名空间。

`data/sources.json` 保存原始报文及站点页面。连续响应由来源按同一进程内的观察次数提供。阶段从 `initial` 启动，本地演练人员可用 `POST /scenario/阶段名` 切换，未覆盖的路由延用初始响应。切换不清空来源的请求记录。重开服务会复位。

执行 `npm test` 核对来源契约。本机浏览器依赖由 Playwright 1.56.1 提供，可在首次准备时执行 `npx playwright install chromium`。容器方式可先执行 `docker build -t archive-filing-sources .`，再执行 `docker run --rm archive-filing-sources`。镜像准备完成后的验证不需要外网。
